## 1. MythicNode Vocabulary — Canonical Definition (First Pass)

### 1.1 Node Types

All nodes live in a new table `mythic_nodes` (or can be derived views initially). Every node has:

- `id` (uuid)
- `type` (enum below)
- `owner_id` (nullable — the primary artist who "owns" this node in their legend)
- `source_table` + `source_id` (traceability back to canonical rows)
- `payload` (jsonb for flexible attributes)
- `occurred_at` / `created_at`
- `embedding` (vector) for similarity (optional in first pass)

**Core Node Types (MVP):**

| Node Type            | Description                                                                 | Primary Source Tables                  | Example Payload Keys |
|----------------------|-----------------------------------------------------------------------------|----------------------------------------|----------------------|
| `artist_profile`     | A creator identity (DJ/producer/curator)                                    | `profiles`, `artist_goals`             | `username`, `genres[]`, `base_city`, `verified` |
| `mix`                | Published long-form audio work                                              | `mixes`                                | `title`, `genre`, `tags[]`, `play_count`, `waveform_url` |
| `buzz`               | Short-form social signal / post                                             | `buzzes`                               | `text`, `attached_mix_id`, `engagement_score` |
| `event`              | Real-world or virtual occurrence (gig, radio session, festival set, workshop) | Manual entry + derived from opportunities + future "I played here" | `venue_id`, `date`, `role` (headline/support), `attendance_estimate` |
| `venue`              | Physical or virtual space with booking history                              | Manual seed + derived from events      | `name`, `city`, `capacity`, `typical_genres[]` |
| `opportunity`        | Curated call / opening (gig, grant, residency, collab, radio, contest)      | `opportunities` (migration 029)        | `opp_type`, `deadline`, `genres[]`, `roles[]`, `compensation` |
| `promoter` / `label` / `curator` | Institutional or individual entity that books, releases, or amplifies | Manual seed + future ingestion        | `name`, `focus_genres[]`, `city` |
| `quest`              | Agent-generated narrative goal with milestones (synthetic but first-class) | Generated by Mythic Agents             | `title`, `timeframe_days`, `target_scene`, `status` (active/completed/abandoned) |
| `agent`              | A Lua agent instance (user-owned or system strategic agent)                 | `lua_agents`                           | `name`, `trigger_types[]`, `run_count`, `persona` |

### 1.2 Edge Types (Relationships & Actions)

Edges live in `mythic_edges`:

- `id`
- `from_node_id`, `to_node_id`
- `type` (enum below)
- `weight` (float, default 1.0 — used for scoring)
- `occurred_at`
- `metadata` (jsonb: role, context, agent_id if generated by agent, etc.)
- `source_event` (for audit)

**MVP Edge Vocabulary:**

| Edge Type                    | Meaning (directional)                          | Example Use Case                                      | Creates Narrative Value? |
|-----------------------------|------------------------------------------------|-------------------------------------------------------|--------------------------|
| `performed_at`              | artist → event/venue                           | "I played at Fuse on 2026-05-17 as support"           | High (core career memory) |
| `booked_by`                 | artist → promoter / venue                      | Attribution of who actually gave the opportunity      | High |
| `submitted_to`              | artist/mix → opportunity                       | Track applications even if not yet accepted           | Medium-High |
| `collab_with`               | artist ↔ artist (via mix or explicit)          | Co-production or joint live set                       | High |
| `remixed`                   | mix → mix                                      | "My remix of X was released on Y"                     | Medium |
| `engaged_with`              | artist → mix/buzz (with weight)                | Plays, likes, reposts, comments, saves                | Medium (volume signal) |
| `recommended_by_agent`      | agent → opportunity / artist / quest / action  | "My Mythic Agent surfaced this and I acted on it"     | Very High (explainability) |
| `followed`                  | artist → artist                                | Social graph (already exists, promote to mythic)      | Low-Medium |
| `inspired_by`               | artist → mix / artist (weaker signal)          | "This set changed how I approach X"                   | Medium |
| `quest_milestone`           | artist/quest → event/opportunity/mix           | "Completed milestone: played at first Belgian festival" | Extremely High (story) |
| `yielded_outcome`           | content/action → real_world_result             | "This buzz + agent suggestion → this actual booking"  | Highest (the attribution flywheel) |

### 1.3 Mapping Current MIXHIVE Data → MythicNode (Phase 6 Starting Point)

- Every `profile` → `artist_profile` node (backfill job)
- Every published `mix` → `mix` node + `created` edge from artist
- Every `follow` → `followed` edge
- Every `opportunity_save` / application → `submitted_to` edge + optional `quest_milestone`
- Future: "I played this gig" button or calendar sync → `performed_at` + `booked_by`
- Every successful Lua agent run that surfaces something → `recommended_by_agent` edge

**Derivation Strategy (Codex):**
- Initial backfill script (one-time + periodic).
- Postgres triggers on key tables (`mixes`, `opportunity_saves`, `follows`, future `events`).
- Background worker (via `audio_jobs` pattern or new `mythic_graph_jobs`) for heavier derivations (similarity, embeddings, quest progress).

## 2. Flagship Feature 1: Mythic Quest Lines

### 2.1 Product Concept

A **Mythic Quest** is a time-bounded, agent-maintained narrative mission that turns abstract career goals into a sequence of concrete, graph-aware actions and milestones.

**Example Quest (auto-generated or user-initiated):**
> "Break into the Brussels Melodic Techno / Leftfield Scene — 90 Day Orbit"

**What the user sees:**
- A beautiful "quest card" in Dashboard / Agents / Profile.
- Progress bar with 4–6 milestones (e.g., "Get 3 plays from local curators", "Play a 60min set at a qualifying venue", "Secure one collab with an artist already in the scene").
- Agent-generated weekly "next best action" cards.
- A living "quest log" (auto-populated from graph events: "Day 17 — You were reposted by Kiosk Radio's selector. +12 momentum").
- On completion: a shareable "Legend Entry" (beautiful image + story) that can be exported to press kits / IG carousels.

### 2.2 MythicNode Involvement

**Nodes heavily used:**
- `quest` (primary)
- `artist_profile` (target scene members)
- `venue`, `event`, `opportunity`
- `mix`, `buzz`

**Edges heavily used:**
- `performed_at`, `submitted_to`, `recommended_by_agent`, `quest_milestone`, `yielded_outcome`, `engaged_with`

**Graph queries the agent will run:**
- "Artists in my genres who have performed_at venues in Brussels in the last 18 months and have >X engagement on recent mixes"
- "Opportunities whose genres overlap my quest target and whose deadline is inside the quest window"

### 2.3 Lua Mythic Agent Behavior ("Scene Orbit Agent" persona)

**Persona:** Strategic Scene Navigator — calm, data-driven, slightly poetic about underground culture. Never hype.

**Trigger:** `on_schedule` (weekly) + `manual` + opportunity-related events.

**Tools it needs (new mh.* surface — see Doc 13):**
- `mh.get_similar_artists_in_scene(artist_id, scene_tags, radius_km, limit)`
- `mh.get_venues_with_history(genres, city, min_bookings_for_similar_artists)`
- `mh.get_relevant_opportunities_for_quest(quest_id)`
- `mh.propose_quest_milestones(quest_id)` (returns structured steps)
- `mh.record_quest_progress(quest_id, milestone_id, evidence_node_ids[])`

**Weekly Pass Flow (pseudo-Lua):**

```lua
function on_schedule(event)
  local quest = mh.get_active_quest_for_owner()  -- or create if none fits "scene growth"
  if not quest then return end

  local recent_activity = mh.get_recent_graph_activity(mh.owner_id, 30)
  local nearby_nodes = mh.query_mythic_graph({
    from = mh.owner_id,
    within_scene = quest.target_scene,
    edge_types = {"performed_at", "engaged_with", "collab_with"},
    window_days = 90
  })

  local proposals = mh.propose_next_actions(quest, recent_activity, nearby_nodes)

  for _, p in ipairs(proposals) do
    mh.notify_quest_update(quest.id, p)   -- creates beautiful in-app card + quest log entry
    mh.create_recommended_by_agent_edge(p.target_node, quest.id)
  end

  mh.update_quest_momentum(quest.id, calculate_momentum(recent_activity))
end
```

**Safety / UX Constraints:**
- Agent can only *propose* milestones and actions. User must explicitly accept or edit.
- All proposals surface in a "Mythic Suggestions" inbox (same pattern as current AI suggestions).
- No auto-application to opportunities.
- User can "pause quest" or "abandon with learning" (learning is captured as a node/edge for future agents).

### 2.4 MVP Scope (Phase 6)

- Quest creation flow (agent-suggested + manual "Create Quest" with template scenes: "Brussels Techno", "Ghent Experimental", "EU Festival Circuit", "Label Demo Orbit").
- Basic `quest` + `quest_milestones` tables.
- One strategic Lua agent template ("Scene Orbit Agent") that runs weekly.
- Dashboard widget showing active quest + top 3 next actions.
- Quest log (append-only events).
- Export "Legend Card" as image (simple canvas or server-side).

**Data/Infra for Codex:**
- New tables: `quests`, `quest_milestones`, `quest_events`
- Backfill + trigger logic to create `performed_at` / `submitted_to` edges from existing data + new user actions.
- New Lua stdlib functions (see Doc 13).
- Storage for quest-generated narrative text and image assets.

## 3. Flagship Feature 2: Agent-Curated Collab Web (Collab Triangles + Yield Attribution)

### 3.1 Product Concept

Instead of a generic "find collaborators" search, the agent surfaces **high-yield collab opportunities** based on actual graph patterns:

- "Artists whose mixes you and your fans both engage with heavily"
- "Producers who have previously collabed with artists you have performed with"
- "People in your travel radius who just got booked by the same promoter who booked you last month"

The output is not a list of profiles — it is a **"Collab Mission"** card:

> **Collab Mission: "Parallel Signal" with @otherartist**
> - 3 of your recent listeners also saved 2 of their mixes in the last 60 days.
> - You both played at [Venue X] within 4 months of each other.
> - Their last collab with @thirdartist led to a Kiosk Radio appearance 11 months later.
> **Suggested first move:** Listen to their latest mix (link). Draft a short, specific note referencing the shared listener overlap.

### 3.2 MythicNode Involvement

**Critical new capability:** Efficient "triangle" and "path of length 2–3" queries over the graph.

**Key edges:** `collab_with`, `engaged_with` (weighted), `performed_at`, `followed`, `recommended_by_agent`

### 3.3 Lua Agent Behavior ("Collab Weaver" persona)

**Weekly + on new mix upload by followed artists.**

**New tools needed:**
- `mh.find_collab_triangles(artist_id, min_shared_signals, max_distance_km)`
- `mh.get_yield_history_for_collab_pattern(pattern_signature)` — looks for past "similar artists did X collab → got Y outcome"
- `mh.draft_collab_outreach(artist_id, context_nodes)`

**Safety:** Draft only. User edits + sends (or copies to email/IG).

### 3.4 MVP

- One "Collab Weaver" strategic agent.
- Collab Mission cards in a new "Mythic Weave" section or integrated into Discover/Agents.
- Simple triangle detection via Postgres recursive CTE + embedding similarity on profiles/genres.
- Manual "Mark as Collab" action that creates `collab_with` edge + optional `yielded_outcome` later.

## 4. Flagship Feature 3: Career-Level AI DJ / Mythic Narrator

### 4.1 Product Concept

Inspired by Spotify's AI DJ, but for the *creator's own career trajectory*.

The agent can be summoned in a chat-like interface ("Talk to your Mythic Self") or can proactively surface "Chapter Updates."

**Example Narrative Session:**

> [Agent voice, calm, low-fi]
> "Chapter 4: The Ghent Anchor. In the last 11 weeks you've released two mixes that accumulated 47% of your total plays from Belgian listeners. Your engagement triangle with @selvagem and @nosedrip is the strongest it's been. 
> 
> The highest-yield pattern right now is 'local venue → regional radio → small festival support.'
> 
> Two concrete moves have 3x the historical success rate of cold submissions right now:
> 1. Submit to the upcoming [specific opportunity] — 4 artists with similar 90-day graphs to yours who submitted last cycle all got responses.
> 2. Reach out to the booker at [specific venue] referencing the shared bill with [artist] in March. Your combined listener overlap is in the top 12% for that room."

This is *not* generic motivation. It is a living, queryable story assembled from the user's actual MythicNode subgraph.

### 4.2 Implementation Sketch

- New "Mythic Narrator" wasmoon-based strategic agent (or extension of existing strategic runtime).
- It has read-only access to the user's full MythicNode neighborhood + aggregated anonymized patterns from similar artists.
- Generates chapters as structured events that can be rendered beautifully.
- User can "ask follow-up" in natural language (first pass: buttons + limited text that maps to graph queries).

**Unique MIXHIVE advantage:** Because the agent runs in the user's own Lua sandbox context (or a privileged strategic version), the narrative can reference private signals (your actual application drafts, your KV-stored notes) that no centralized Spotify-style model can ever see.

## 5. Flagship Feature 4: Opportunity Routing & Attribution Engine (The Attribution Flywheel)

### 5.1 Product Concept

Every time a user takes a meaningful action (posts a buzz, uploads a mix, runs an agent, saves an opportunity, plays a venue), the system can later ask or infer:

"Did this action contribute to a real outcome?"

Outcomes are first-class: actual bookings, label interest, collab releases, grant awards, radio plays.

The agent then surfaces:

- "Your top 3 career-yield actions in the last 6 months were all related to [specific micro-scene + one promoter]."
- "Artists who posted 2+ pieces of content about their [Venue X] gig within 10 days of the show converted 2.4x better into follow-up bookings."

This turns the platform into a **personal laboratory** for career strategy.

### 5.2 MythicNode Backbone

`yielded_outcome` edges are the crown jewels. They close the loop.

### 5.3 MVP

- Lightweight "Log an Outcome" flow (user-driven + agent-suggested).
- Basic yield scoring on actions and content nodes.
- One dashboard panel: "What actually moved the needle for you?"
- Agent that proposes "Double down on X pattern" suggestions.

## 6. Cross-Cutting UX Principles (for Claude Code)

- **Agent as trusted advisor, never as boss.** Every suggestion has "Accept / Edit / Dismiss / Tell me why" actions.
- **Provenance always visible.** When an agent recommends something, the user can click "Why?" and see the actual nodes and edges (in human language).
- **Quests and Narratives are beautiful first-class objects.** Not buried in settings.
- **Everything degrades gracefully.** If the graph is sparse for a new user, fall back to strong defaults + gentle onboarding that accelerates graph population ("Tell us about 3 recent gigs you've played").
- **Tone:** Underground-literate, anti-hype, precise, slightly mythic/poetic but never cringe.

## 7. Summary — What Makes These Features Uniquely MIXHIVE

| Feature                    | SoundCloud / Splice / VI.BE Can Copy? | Why It's Hard Without MythicNode + Lua Agents |
|----------------------------|---------------------------------------|-----------------------------------------------|
| Dynamic, graph-backed Quests with real milestones | Surface level only | Requires persistent attributed graph + safe per-user execution environment |
| Collab triangles with historical yield | No memory layer | Needs multi-hop queries + outcome attribution |
| Career AI Narrator that references your private actions and real bookings | Impossible (privacy + data model) | Only possible when agent runs in user context with full graph access |
| Explainable "this action actually led to this booking" attribution | No structured outcome tracking | Core data model commitment |
